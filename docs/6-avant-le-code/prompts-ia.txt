========================================
LES PROMPTS IA - LE CŒUR DE LA QUALITÉ LITTÉRAIRE
========================================
Projet : Fable
Date : 03/09/2026
But : définir les prompts (instructions) donnés à l'IA pour
écrire les romans. C'est LA clé de la qualité. Toutes les
décisions produit (6-avant-le-code/decisions-produit.txt) et
les règles d'écriture (5-ecriture-narrative/) se retrouvent ici.
Fichiers liés : 5-ecriture-narrative/*.txt, 4-produit/
fonctionnalites.txt, 2-analyse-strategique/choix-fournisseur-ia.txt

================================================================
0. ARCHITECTURE DES PROMPTS (vue d'ensemble)
================================================================
CINQ types de prompts (dans l'ordre de la vie d'un roman) :
1. PROMPT STORY BIBLE   -> plan complet du roman (JSON)
2. PROMPT PROLOGUE      -> chapitre 0 (hook), génère la couverture
3. PROMPT CHAPITRE      -> chaque chapitre (1 à N)
4. PROMPT FIN           -> climax + dénouement + épilogue (2-5 fins)
5. PROMPT RÉSUMÉ        -> compression de l'historique (cohérence)

=> Tous les prompts doivent :
   - être en français, demander une sortie en français
   - exiger un format JSON (pour la fiabilité du code)
   - inclure les règles anti-AI-slop (voir §7)
   - inclure l'ÂGE de l'utilisateur (adapter le contenu)
   - inclure les paramètres (genre, style, longueur, choix,
     difficulté)

================================================================
1. PROMPT STORY BIBLE (généré UNE fois par roman)
================================================================
ROLE : créer le plan complet avant d'écrire. Garantit la
cohérence de tout le roman.

MODÈLE (extraits - à compléter à l'implémentation) :
---
Tu es un grand romancier. Crée la "bible" d'un roman
interactif (livre dont le lecteur est le héros).

GENRE : {genre} {sous-genre éventuel}
PUBLIC : {tranche d'âge} (adapte violence/romance/horreur)
PARAMÈTRES : difficulté {facile/moyenne/difficile}, style
narratif {style}, {longueur} chapitres, {nb_choix} choix max.

Règles de fond (issues de 5-ecriture-narrative/) :
- Structure en 3 actes (exposition/confrontation/résolution).
- UNE question dramatique centrale, répondue au climax.
- Un héros imparfait : désir, peur, faille, secret.
- Un antagoniste avec une motivation (jamais "méchant pour
  être méchant").
- Un monde cohérent (règles stables, magie/science/époque).
- 2-5 fins possibles selon les choix.

Réponds UNIQUEMENT en JSON valide avec :
{
  "titre": "...",
  "genre": "...",
  "sousGenre": "...",
  "questionDramatique": "...",
  "theme": "...",
  "resumeGeneral": "...",
  "structure": {"acte1": "résumé", "acte2": "résumé",
                "acte3": "résumé"},
  "heros": {"nom": "...", "desir": "...", "peur": "...",
            "faille": "...", "traitOptionnel": "..."},
  "antagoniste": {"nom": "...", "motivation": "..."},
  "personnages": [{"nom": "...", "role": "...", "detail": "..."}],
  "monde": {"description": "...", "regles": "..."},
  "finsPossibles": [{"nom": "...", "condition": "..."}],
  "tonStyle": "..."
}
---
L'IA RENVOIE LA BIBLE. On la STOCKE (Supabase) et on la
réutilise à chaque chapitre (via le résumé).

================================================================
2. PROMPT PROLOGUE (chapitre 0 + couverture)
================================================================
ROLE : créer le chapitre 0 (hook) puis décrire la couverture.

MODÈLE :
---
Tu es un grand romancier. Écris le PROLOGUE de ce roman.

BIBLE DU ROMAN :
{story_bible}

PUBLIC : {âge} | STYLE : {style} | LONGUEUR : {cible_mots}

Le prologue doit :
- ACCROCHER immédiatement (une scène intrigante, un danger,
  une question, un mystère) - pas de description poussée du
  monde ici.
- Poser le héros et son monde ordinaire (avant la bascule).
- Finir sur une note qui donne envie de lire le chapitre 1.
- Ne PAS contenir de choix (les choix commencent au chapitre 1).

Réponds en JSON :
{
  "titre": "Prologue",
  "texte": "..." (le prologue),
  "descriptionCouverture": "description visuelle détaillée de
    la couverture (style de l'image, ambiance, couleurs,
    héros, lieu) - pour un générateur d'images",
  "choix": []
}
---
=> La descriptionCouverture est envoyée au prompt image.

================================================================
3. PROMPT CHAPITRE (chaque chapitre 1 à N)
================================================================
ROLE : écrire un chapitre du roman + proposer 2-4 choix.

MODÈLE :
---
Tu es un grand romancier. Continue ce roman.

BIBLE DU ROMAN :
{story_bible}

RÉSUMÉ DES ÉVÉNEMENTS PRÉCÉDENTS (texte courant) :
{resume_historique}

DERNIER CHOIX DU HÉROS : {choix_du_joueur}

INFO CHAPITRE : Chapitre {n}/{total}. Position narrative :
{acte}. {phase_du_chapitre} (ex : montée de tension, point de
bascule, avant-climax...)

PUBLIC : {âge} | STYLE : {style} | DIFFICULTÉ : {difficulté}
LONGUEUR : ~{mots} mots. NB DE CHOIX À PROPOSER : 2 à {nb_max}.

RÈGLES D'ÉCRITURE (5-ecriture-narrative/) :
- Le chapitre doit avoir un début qui relance, un développement
  (1-3 scènes), une fin variée (clôture / suspense doux /
  CLIFFHANGER).
- Progression de l'arc : on avance vers le climax de l'acte.
- Le héros agit selon son trait (s'il en a un) mais le joueur
  garde le contrôle via les choix.
- Conséquences visibles des choix précédents.
- {règle_fin_chapitre} (ex : chapitre 5 = finir sur un
  cliffhanger maximal - c'est la fin de l'essai gratuit).
- Adapte violence/romance/horreur à {âge}. {limite_âge}
- 2e personne ("tu") OU 3e personne interne selon le mode choisi.

Écris en JSON :
{
  "titre": "Chapitre {n} : ...",
  "texte": "..." (le chapitre),
  "choix": [
    {"libelle": "Frapper la porte du regard de l'étranger",
     "conséquenceRésumée": "..."},
    ...
  ]
}
- Les libellés des choix sont ÉVOCATEURS (montrent l'action et
  l'enjeu), pas génériques ("Ouvrir la porte").
- Chaque choix a une conséquence résumée (pour la cohérence
  et l'éventuel rappel).
- Les choix ne doivent pas être des fausses options : chacun
  mène à une suite réellement différente.
---
=> Un chapitre de génération IA = 1 chapitre de roman. La
   qualité dépend de ce prompt.

================================================================
4. PROMPT FIN (climax + dénouement + épilogue)
================================================================
ROLE : conclure le roman (climax, dénouement, épilogue). Utilise
un modèle de QUALITÉ (Claude Sonnet 5 / Opus 5) - c'est le
moment le plus important.

MODÈLE :
---
Tu es un grand romancier. Écris la FIN de ce roman.

BIBLE DU ROMAN :
{story_bible}

RÉSUMÉ DES ÉVÉNEMENTS PRÉCÉDENTS :
{resume_historique}

PARCHEMENT DU HÉROS : {résumé des choix majeurs}

FIN À ÉCRIRE : {type_fin} (parmi les fins possibles de la
bible). Le héros arrive au CLIMAX : la question dramatique
"{questionDramatique}" trouve sa réponse.

PUBLIC : {âge} | STYLE : {style} | DIFFICULTÉ : {difficulté}

Règles :
- CLIMAX : le point culminant, l'affrontement/résolution qui
  répond à la question dramatique posée à l'acte 1.
- DÉNOUEMENT : court - les conséquences, le sort du héros.
- ÉPILOGUE : bref - le monde après l'histoire, une note
  émotionnelle qui reste.
- La fin doit être satisfaisante, cohérente avec les choix du
  joueur, et logique.
- {limite_âge} (adapter violence/mort selon l'âge ; en mode
  doux le héros ne meurt pas même en échec).

Écris en JSON :
{
  "titre": "Chapitre final : ...",
  "texte": "...",
  "typeFin": "victoire/échec/tragique/ouverte/...",
  "epilogue": "..." (optionnel, si distinct),
  "choix": []  (fin du roman, plus de choix)
}
---

================================================================
5. PROMPT RÉSUMÉ (compression de l'historique)
================================================================
ROLE : résumer l'historique à chaque étape pour :
- maintenir la COHÉRENCE longue (l'IA ne peut pas tout
  re-lire) ;
- ÉCONOMISER les tokens (le résumé coûte peu vs tout rejouer).

MODÈLE :
---
Résume en un texte bref et précis les événements d'un roman
pour permettre à un autre rédacteur de continuer l'histoire
sans relire les chapitres. Inclus : les choix majeurs du
héros, les personnages rencontrés, les révélations, l'état
émotionnel, les conséquences. Garde les faits importants,
omets les descriptions.
---
=> S'exécute après chaque chapitre (ou tous les 2-3) et
   produit un "résumé courant" stocké et réinjecté.

================================================================
6. PROMPT IMAGE (illustrations à la demande + couverture)
================================================================
ROLE : générer les prompts pour le générateur d'images
(FLUX.1 Dev via fal.ai / DALL-E en option).

MODÈLE (transforme une demande en prompt image) :
---
Transforme cette demande en prompt d'image détaillé (en
français), style "illustration de livre", cohérent avec
l'univers et l'ambiance du roman. Précise : sujet, action,
décor, éclairage, ambiance, palette de couleurs, style
artistique. Interdit : texte dans l'image, visages déformés.

DEMANDE : {demande_du_joueur}
CONTEXTE : {résumé + description du moment}
---
=> L'app envoie le résultat au service d'images.

NB COÛT : chaque image = crédits (voir economie-app.txt).

================================================================
7. RÈGLES ANTI-"AI-SLOP" (À INSÉRER DANS TOUS LES PROMPTS)
================================================================
À ajouter systématiquement :
- "Écris en français naturel et soigné, comme un écrivain
  confirmé. Évite les tournures typiques de l'IA."
- "Interdit : les formules creuses ('dans un monde où...',
  'il était une fois un jeune homme destiné à...'), les
  superlatifs vides, les répétitions, le vocabulaire générique."
- "Montre, ne dis pas : utilise des actions, des détails
  concrets et des sensations au lieu de déclarations
  abstraites."
- "Varie la longueur des phrases et des paragraphes. Alterne
  action, dialogue, description et introspection."
- "Les dialogues sonnent naturels, avec des voix distinctes."
- "Respecte strictement la structure JSON demandée - rien
  d'autre que le JSON."
- "Ne mentionne jamais que tu es une IA. Ne casse pas le 4e
  mur."

================================================================
8. MODÈLES IA PAR PROMPT (rappel choix-fournisseur-ia.txt)
================================================================
- STORY BIBLE      : Claude Sonnet 5 (qualité, une seule fois)
- PROLOGUE         : Claude Sonnet 5 (qualité du hook)
- CHAPITRE courant : GPT-5.6 Luna (coût, volume)
- FIN / CLIMAX     : Claude Sonnet 5 / Opus 5 (le meilleur)
- RÉSUMÉ           : GPT-5.6 Luna (simple, pas cher)
- IMAGE            : FLUX.1 Dev (fal.ai ~0,02 $) / DALL-E opt.
=> La couche d'abstraction permet de basculer chaque type de
   prompt vers un autre fournisseur sans changer le code.
